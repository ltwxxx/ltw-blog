## 1. 软件概述

### 1.1 软件名称与定位

本软件为**个人主页 / 个人博客静态站点生成与部署工具**。用户通过维护 `data` 目录下的 JSON、Markdown、PDF 及图片等素材，运行生成程序将**内容**与 **Jinja2 HTML 模板**合并，输出完整静态网页至 `html` 目录；可选用 **Docker + Nginx** 一键部署，对外提供高可移植的静态站点服务。

### 1.2 主要功能（与登记申请表表述应对齐）

| 序号 | 功能模块 | 说明 |
|:---:|---------|------|
| 1 | **首页（Home）** | 单页长滚动首页：导航、Hero 主视觉、各栏目的预览区块（简历/博客/项目等摘要）。 |
| 2 | **简历（Resume）** | 独立简历页：展示/下载 `resume.pdf` 等简历相关静态内容。 |
| 3 | **博客（Blog）** | 扫描 `data/blog` 下分类与文章，生成博客列表卡片、文章详情页；正文支持 **Markdown** 渲染；图片支持懒加载。 |
| 4 | **项目（Project）** | 与博客类似的卡片 + 详情结构，用于个人项目展示。 |
| 5 | **文档下载（Docs）** | 根据 `files.json` 生成文档列表页，支持 Markdown、PDF 等文件的展示与下载信息。 |
| 6 | **技术栈（Stack）** | 根据 `stack.json` 生成技术栈展示（含图标映射等）。 |
| 7 | **联系（Contact）** | 联系方式、社交信息等展示页。 |
| 8 | **留言板（Guestbook）** | 留言板独立页面与首页预览区（表单文案等由 `title.json` 配置；具体提交逻辑以当前实现为准）。 |
| 9 | **统一生成入口** | `gen.py` 支持按模块或 `all` 全量生成；生成前对已选模块输出目录做清理，保证与 `data` 同步。 |
| 10 | **生产部署** | 多阶段 **Dockerfile**：构建阶段执行 `python gen.py all`，运行阶段使用 **Nginx** 托管 `html`，默认容器端口 **83**，宿主映射常见为 **8081**。 |

### 1.3 技术特点（与登记申请表表述应对齐）

- **内容、模板、构建脚本分离**：内容在 `data`，版面在 `templates`，逻辑在 `scripts` 与根目录 `gen.py`，便于维护与二次开发。  
- **静态站点生成（SSG）**：无服务端业务运行时依赖；输出为标准 HTML/CSS/JS 静态资源，易于 CDN、对象存储与任意 Web 服务器托管。  
- **模板引擎**：**Jinja2** 组织公共导航、页脚、卡片等组件。  
- **Markdown**：**Python-Markdown** 将博文与项目正文转为 HTML。  
- **工程化部署**：**Docker 多阶段构建**减小运行镜像体积；**Nginx** 配置默认页 `home.html`、`gzip`、静态资源长缓存与安全响应头；`try_files` + 自定义 404 行为提升单页应用式路由体验。  
- **可配置导航顺序**：`data/order.json` 定义栏目顺序，与各页 `frame.json` 中 `nav_title` 等合并为全站导航。

### 1.4 源程序量说明（请以申请表最终填写为准）

在本仓库**仅统计与软件直接相关的 `gen.py`、`scripts/` 下 Python 源文件**（不含 `__pycache__`）：合计约 **2385 行**。  
**`templates/`** 下 HTML 等模板文件合计约 **3047 行**。

## 3. 获取软件与目录结构

软件根目录（示例）主要结构如下：

```text
├── data/                 # 站点内容与配置（用户主要编辑此处）
├── templates/            # Jinja2 模板
├── scripts/              # 各页面生成逻辑
├── html/                 # 生成的静态站点输出（提交前或构建后产生）
├── gen.py                # 统一生成入口
├── requirements.txt
├── Dockerfile            # 多阶段构建 + Nginx
├── nginx.conf            # 站内 Nginx 配置
├── run-docker.sh         # 一键构建运行容器（可选）
└── serve.sh              # 本地静态预览 html（可选）
```

## 4. 安装与部署

### 4.1 本地安装依赖

在软件根目录执行：

```bash
cd /path/to/第二版个人博客
python3 -m pip install -r requirements.txt
```

【图 1】终端执行成功界面（显示已安装 jinja2、markdown 等）。

### 4.2 生成静态站点

全量生成：

```bash
python3 gen.py all
```

仅生成部分模块（示例）：

```bash
python3 gen.py blog project
```

可用目标：`home`、`resume`、`blog`、`project`、`docs`、`stack`、`contact`、`guestbook`、`all`。

【图 2】终端显示各模块 “✅ … 生成完成” 的完整输出。

### 4.3 本地预览（不依赖 Docker）

确保已执行生成且存在 `html` 目录后：

```bash
chmod +x serve.sh
./serve.sh
```

默认在 **9000** 端口静态服务 `html`，浏览器访问提示中的地址（如 `http://localhost:9000/home.html`）。

【图 3】终端运行 `serve.sh` 的界面；**【图 4】** 浏览器打开首页 `home.html`，地址栏与页面完整可见。

### 4.4 Docker 构建与运行

在软件根目录：

```bash
chmod +x run-docker.sh
./run-docker.sh
```

默认将容器 **83** 映射到宿主 **8081**。若端口占用可设环境变量，例如：

```bash
HOMEPAGE_PORT=8082 ./run-docker.sh
```

【图 5】`docker build` 与 `docker run` 成功信息；**【图 6】** 浏览器访问 `http://localhost:8081`（或自定义端口）显示首页。

### 4.5 与线上环境一致时的访问

若已部署至公网并绑定 HTTPS 域名，用户可直接通过浏览器访问登记材料中填写的站点 URL（如 `https://www.ltw22408.top`）。

【图 7】线上首页完整截图（含地址栏域名）。

## 6. 软件使用流程（内容维护者 — 站点管理员）

### 6.1 修改全局与导航

1. 编辑 **`data/frame.json`**：站点标题、导航 Logo 文案、页脚、SEO 相关字段（如 `site_description`、`site_url`）等。  
2. 编辑 **`data/order.json`**：数组顺序决定导航栏各栏目顺序（如 `home`、`resume`、`blog`…）。  
3. 编辑 **`data/title.json`**：首页 Hero 大标题、副标题、按钮文案与锚点链接等。

【图 18】在编辑器中打开 `frame.json` / `order.json` / `title.json`（可打码隐私字段）。

### 6.2 维护博客与项目内容

- 博客：**在 `data/blog` 下按分类与文章目录**维护 `card.json`、`content.md` 及配图（相对路径引用）。  
- 项目：结构类似，由 `scripts/sections/project` 扫描生成。

保存后执行：

```bash
python3 gen.py blog
# 或
python3 gen.py project
# 或全量
python3 gen.py all
```

【图 19】`data/blog` 目录结构示意；**【图 20】** 修改后重新生成终端输出；**【图 21】** 浏览器刷新后新文章可见。

### 6.3 维护文档下载

- 将可调用的文件放入 **`data/docs`**。  
- 编辑 **`data/docs/files.json`**：配置分组与展示名称。

执行 `python3 gen.py docs`（或 `all`）后刷新「文档」页。

【图 22】文档页出现新文件条目。

### 6.4 维护技术栈与联系、留言板文案

- **技术栈**：`data/stack/stack.json` 等。  
- **联系**：`data/contact/` 下 JSON 与图片资源。  
- **留言板**：`data/guestbook/title.json`、`frame.json`。

分别生成：

```bash
python3 gen.py stack contact guestbook
```

## 8. 常见问题

**Q：修改了 `data` 但网页没变？**  
A：需重新运行 `python3 gen.py …` 对应模块或 `all`；若用容器部署，需重新构建镜像或挂载新生成的 `html`。

**Q：本地端口冲突？**  
A：`serve.sh` 可用环境变量 `PORT`；Docker 可用 `HOMEPAGE_PORT`。

**Q：申请表中的功能与本文不完全一致？**  
A：以**申请表为准**修订第 1.2、1.3、1.4 节的文字，并删改不存在的功能截图，保持全文一致。
